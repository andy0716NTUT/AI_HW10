W01 / 核心概念

什麼是 AI Agent？

能根據目標決定下一步、選擇工具並利用結果持續完成任務的 AI 系統；並非所有 LLM 應用都需要 Agent。

  • 一般單次 LLM 呼叫可直接產生回答；聊天介面也可能接上工具，不能只看介面判斷是否為 Agent。
  • Agent 可以在執行過程中動態決定是否查詢資料、呼叫工具與重試。
  • Workflow 則更偏向由程式事先定義流程。

教學情境：請幫我把五篇 Agent 文件整理成有來源的學習簡報；系統需要取得資料、整理並檢查。

W02 / 核心概念

Agent 的四個基本元件（教學整理）

模型負責推理；指令定義界線；工具執行動作；狀態／記憶保存需要的上下文。

  • Model：判斷使用者需求和下一步。
  • Instructions：規定任務、格式、行為與限制。
  • Tools：搜尋、計算、讀取 API、寫入系統等。
  • State / Memory：保存當前執行資訊與必要的歷史知識。
  • 此四項是本教學的整合框架：OpenAI 提出模型、工具、指令，另以 Google Cloud 的狀態／記憶補充。

W03 / 運作方式

工具呼叫與回饋迴圈

「推理 → 使用工具 → 取得結果 → 再推理」是常見的 agent loop。

  • 模型先判斷目前資訊是否足夠。
  • 不足時選擇工具及其參數。
  • 執行環境實際呼叫工具並回傳結果；模型不是憑空執行外部 API。
  • 模型檢查結果，決定回答、再次查詢或交由人工處理。
查看教學示例

工具呼叫示意：模型提出 search_wiki(query="工具迴圈")；執行環境查詢 Wiki，將 W03 回傳給模型。這是教學示意，並非本程式呼叫 LLM 的紀錄。

W04 / 運作方式

Workflow、Agent 與 Graph

Workflow 流程較固定；Agent 可動態選擇路徑；Graph 用節點、邊與條件把流程視覺化。

  • 節點 Node：取得、摘要、驗證、生成等處理步驟。
  • 邊 Edge：資料或控制流向。
  • 條件 Edge：若內容檢查不通過，就回到指定節點。
  • 複雜流程不必然比簡單流程更好；應依需求選擇。

狀態示例：query、retrieved_ids、draft、errors、retry_count。若引用檢查失敗，就帶著錯誤回到檢索節點。

W05 / 設計模式

常見設計模式

串接、分類路由、平行、主控分工、評估優化等模式用於不同任務。

  • Prompt chaining：上一階段輸出送入下一階段。
  • Routing：先分類，再走適合的子流程。
  • Parallelization：拆分可獨立完成的部分。
  • Evaluator–optimizer：產出後由評估器檢查，不合格則修正。
查看教學示例

例：先整理來源，再起草摘要，最後檢查引用；不合格就回到檢索與起草。

W06 / 實務設計

安全性、驗證與人類介入

Agent 需要可追蹤來源、限制工具權限、檢查輸出，風險較高的動作應經人工確認。

  • 檢查來源是否真的支持結論，避免模型編造內容。
  • 限制工具能執行的操作及其權限。
  • 設定最大重試次數，避免無限迴圈。
  • 可把人工核准設成寫入、刪除等敏感操作的先決條件。

練習：若引用不存在，應先回檢索／引用檢查；重試到上限仍失敗，就停止輸出並回報。
