03 / CONCEPT03 / 10

Chatbot ≠ Agent

Chatbot：多半直接回答。Agent：可依任務狀態決定要不要使用工具、是否繼續。

例：問「台北天氣如何？」是回答問題；「查天氣後整理出門清單」可能需要查詢工具與多步驟處理。

04 / BUILDING BLOCKS04 / 10

Agent 的四個元件

MODEL　→　INSTRUCTIONS　→　TOOLS　→　STATE / MEMORY

MODEL→INSTRUCTIONS→TOOLS→STATE

模型做判斷；指令定規則；工具能查詢或動作；狀態保存過程資料。

05 / LOOP05 / 10

核心：工具回饋迴圈

觀察任務 → 模型判斷 → 工具執行 → 讀取結果 → 再判斷

THINK→ACT→OBSERVE↺

資訊充分就回答；不足則繼續查詢。要設停止條件與重試上限。

06 / GRAPH06 / 10

Graph 把決策變清楚

Node 是步驟、Edge 是連線、Conditional Edge 是分支。

NODE→CHECK↙ FAILRETRY

例如檢查失敗，不必整份重做；回到有問題的「資料查詢／內容整理」節點即可。

08 / EXAMPLE08 / 10

案例：製作學習摘要

取得問題 → 查 Wiki → 整理 3 個重點 → 查核來源 → 產生摘要

RETRIEVE→SUMMARIZE→VERIFY→OUTPUT

若 Wiki 查不到或引用不支持內容，回到檢索，不要讓無來源敘述進入最終輸出。

09 / SAFETY09 / 10

Agent 為什麼需要檢查？

看似流暢的回答，也可能引用錯誤、操作越權或陷入重試。

來源回溯 + 最小工具權限 + 重試上限 + 敏感操作人工核准。

快速複習

Agent = 決策 + 工具 + 狀態 + 回饋。Graph = 可檢查的執行路徑。

想一想：如果查不到資料，應該回到哪個節點？答案：先回檢索與來源驗證。
